# MESA — Decision Landscape (short)

Complex rehearsals fall apart in the write-up. The plan, the session log, and the score live in different files. A missing observation becomes a zero. The published recap gets edited after the fact.

I built MESA — Decision Landscape as a local prototype of the loop I actually trust. A scenario is a versioned definition: roles, registered actions, injects, and rubric anchors. The graph on screen is a projection of that definition. Solid arrows are recorded conditions. Dashed lines are grouping, not a second plot. A session pins the definition at launch. Commands return receipts, and accepted does not mean executed.

Review is the gate. A finding with no citations cannot be approved. `not_observed` stays non-numeric. Reports publish an exact snapshot; later corrections open an amendment and leave the old one alone. When the model drafts narrative, a person accepts or rejects it against the current version and digest. The model does not publish and does not score participants.

The demo data is a synthetic readiness program (Atlas and Harbor): incident response, recovery, continuity, and crisis tabletop exercises. The pattern is the workflow, not the vertical. The interface uses one token set — Obsidian, Mist, Stone, Basalt, Mineral Gold — with explicit empty states where identity, billing, and invitations are not connected.

It runs on a laptop: TypeScript, a React and Vite host, HTML view renderers, a Node API, and local Supabase. There is no public demo. Persona switching is not authentication. The publication check is a non-cryptographic hash. Most screens are not React yet.
