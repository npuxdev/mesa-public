Replace `harbor` with `atlas` for Atlas. The installer never resets existing GLASSHOUSE records or other user drafts. Browser-tab persistence remains local. The installation supplies an eight-role synthetic roster, not actual users, consent, or invitations. The pinned local source is not an expert-approved or signed production publication.

## Run

1. Open the rehearsal as the fixture manager/facilitator. Review the pinned source and roster. Use the explicitly labelled synthetic roster-ready control, open the lobby, and launch.
2. Release `inj-01` at minute 0. Advance stepped time and release the remaining twelve-source MSEL cues at 15, 24, 30, 45, 55, 60, 75, 82, 90, 105, and 118 minutes. Pause/resume and delayed/canceled cues use existing audited controls. Four decision gates occur at 30, 60, 80, and 105; the public-allegation cue at 75 precedes the 80-minute gate.
3. Participants use Investigate to select a GLASSHOUSE action and submit an attributed request. All nineteen source actions are available as proposals, not automatic execution. The console retains two deliberately narrow registered fixture transitions (independent journal verification and scoped connector restriction); other consequences require facilitator review.
4. Under facilitator Adjudication, select a pending request, matching evidence/action, eligible assigned investigator, and rationale. Explicitly authorize the reveal. The adapter checks source availability time, permitted investigation role, request/action match, duplicate release, and facilitator capability. At minute 90 the audit becomes available, not automatically discovered. Facilitators must document any additional playbook prerequisites and advance action-duration costs explicitly.
5. Use released references for observations, human review, decisions, team notes, and corrective actions. End the simulation at 120 minutes and conduct the 30-minute debrief. Schedule new rehearsals from a published revision; draft edits do not change the existing pinned exercise. Validate and publish an edited fork before using it in a new exercise.

## Mapping and interpretation limits

Eight roles, twelve injects, all nine investigation-answer sources, four gate prompts, six weighted rubric domains (weights total 100), branch guidance, and corrective-action suggestions are retained. Original custom channels map to internal or customer messages. Participant artifacts contain teasers only; answer text requires authorized release. Role briefs and human-readable branch notes remain facilitator-only in authoring/queue projections.

The source uses three point anchors per domain. STRATA uses four 0–3 observation anchors: source zero, source midpoint, adapted effective-response-with-minor-gaps, and source maximum. Original weights are preserved; no exact source 100-point composite or automatic critical-failure calculation is claimed. Critical failures are reviewed separately. The 70% coverage threshold is an explicit adapter default, not a source metric.

Human-readable branch-rule strings are never evaluated. Custom action flags, automatic financial/resource branches, adversary agents, AI director behavior, source-lineage trees, and automatic board reports are not implemented by this adapter. Facilitators review branch guidance in the opening cue's hidden notes and record consequences/assessment impact through existing controls. No real payments, outages, external communications, or cyber actions occur.

This is a client-side synthetic fixture: role projections hide spoilers from participant UI/read models, but compiled browser assets are inspectable and are **not** a secure server-side facilitator vault. Production use requires server-held truths/answers and enforced role/time/action projections. Do not use real confidential data.
